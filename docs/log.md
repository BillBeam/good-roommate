## 2026-10-24 · M1 造世界，测基线（第二版）

- **做了什么**：把第一版对照研究目标的七处问题全部改掉，在 3 个新随机世界（种子 1、2、3，各 24 个用户 × 8 次会话）上重测。
  - 提问要声明问哪几项属性，模拟用户只答这几项，不再用模型归类。
  - 回答由短句表拼成，用一个只看文字的反解器逐条检查前后一致；健康原因的不吃辣，问到饮食限制时一定说出来。
  - 用户记着告诉过 agent 什么，再问只说"之前跟你说过了"。
  - 每个事件改动在台词里都有线索，用两个模型校验。
  - 选项改成"三对近似状态"，不看用户的规则和分类器都选不出答案。
  - 新增理想记忆策略做满分参照，新增"记住所有回答、每次都重问"的捷径，分数只算与偏好有关的会话。

  - 起点小模型如果已经很强，RL 的空间就小。M2 第一步先测未训练的 Qwen3.5-4B，再决定投入。
  - 认出自己那一对选项、少问几项：好处最多是理想记忆策略的提问花费（每次会话 0.064 分），影响不大，但 RL 一定会找到它，M2 里先用脚本策略量出来。
  - 一部分近似项是假想的变化，不检验"察觉变化"。M2 以后的分析要把真变化和假想变化分开统计。

## 2026-10-24 · M1 造世界，测基线（第一版）

- **做了什么**：搭好第一版模拟环境：一批模拟用户各自过好几个月的"生活"，每隔一两周找 agent 办一件事（订晚餐、找午饭、订酒店，或者算账换算）。用户的真实偏好由程序记着，agent 看不到；用户会顺口提到搬家、健身、添宝宝这类事，偏好随之悄悄改变，但从不明说"我变了"；也会说"这次嗓子疼别吃辣"这种只管一次的话。agent 能读写记忆、能问用户（每问一次扣分）。对错由程序按用户当时的真实状态判，不用任何模型打分。之后用三个 xAI 现成模型测了基线，又在一个外部基准（ATRBench）上跑通了它的官方评测脚本。全部用 `python -m roommate.run` 一条命令跑完，报告见 [reports/m1-baseline.md](../reports/m1-baseline.md)。
- **一句话结果**：环境搭好了、判分自检全部通过，但环境过于简单：最强的现成模型不经训练就拿到满分标准的 81%，超过了 80% 的闸门，M1 还不能算过关。
- **关键数字**：
  - 规模：[24](../runs/m1/world_stats.json) 个模拟用户，每人 [8](../runs/m1/world_stats.json) 次会话；其中一个事件同时改动多项偏好 [29](../runs/m1/world_stats.json) 次，临时情况 [24](../runs/m1/world_stats.json) 次，与偏好无关的会话 [24](../runs/m1/world_stats.json) 次。
  - 判分自检：知道真实状态的标准策略得 [1.000](../runs/m1/policies/oracle/summary.json) 分（满分），什么都不做得 [0.000](../runs/m1/policies/nothing/summary.json) 分；全部 [10 项检查](../runs/m1/selfcheck.json)通过。
  - 两种捷径：每次都把问题问一遍，得 [0.674](../runs/m1/policies/ask_all/summary.json) 分，平均每次问 [2.17](../runs/m1/policies/ask_all/summary.json) 次；不做个性化的保守默认，得 [0.312](../runs/m1/policies/conservative/summary.json) 分。
  - 三个现成模型的得分：grok-4.20 [0.416](../runs/m1/policies/llm_grok-4.20-0309-non-reasoning/summary.json)，grok-4.3 [0.570](../runs/m1/policies/llm_grok-4.3/summary.json)，grok-4.7 [0.813](../runs/m1/policies/llm_grok-4.7/summary.json)。grok-4.7 的后续任务成功率 [91.7%](../runs/m1/policies/llm_grok-4.7/summary.json)，因用了过时记忆而选错的比例 [6.3%](../runs/m1/policies/llm_grok-4.7/summary.json)。
  - 弱模型输在不写记忆：grok-4.3 在全部会话里写记忆的比例是 [0.0%](../runs/m1/policies/llm_grok-4.3/sessions.jsonl)，grok-4.7 是 [49.5%](../runs/m1/policies/llm_grok-4.7/sessions.jsonl)。
  - 复现：只用缓存重跑，[10 / 10](../runs/m1/repro_check.json) 个策略逐字一致；在会话中途存档再恢复，[3 / 3](../runs/m1/resume_check.json) 个模型的结果与不中断时一致。
  - 外部基准 ATRBench：1 个人设、[11](../runs/m1/bench/atrbench_summary.json) 个测试会话，grok-4.20 通过 [10](../runs/m1/bench/atrbench_summary.json) 个。
- **没解决的问题**：
  - 环境过于简单。强模型只要老老实实记笔记，就能接住大部分变化。
  - 只跑了一个随机种子，各模型之间的差距有多少是运气，还不知道。
  - 模拟用户把"问题问的是哪方面"这一步交给了一个模型判断，人工抽检的准确率是 [96.7%](../runs/m1/classifier_eval.json)，不是百分之百。
  - ATRBench 只能跑不需要模拟用户的那一种变体（它默认的模拟用户来自其他服务商）；HorizonBench 的数据放在 Hugging Face 上，本环境连不上。
- **下一步**：给环境加难，再测一遍基线，直到最强模型回到 80% 以下。候选办法：
  - 变化说得更隐晦。
  - 会话跨度更长、事件更多，让一项偏好被改两次。
  - 限制记忆条数，逼 agent 取舍。
  - 让事件之间相互影响。
  - 补跑多个随机种子。
- **花费**：约 [5.21 美元](../reports/m1-baseline.md#9-花费)（上限 30 美元）。其中三个模型的正式基线 [4.37 美元](../runs/m1/costs.json)，其余是试跑、模拟用户和 ATRBench 评测。

### 审阅（Claude）

- **复核**：在独立的环境里只用缓存、不联网重跑，10 个策略的逐次记录和隐藏世界文件逐字一致；17 个测试全部通过。复核统计的脚本是 [reports/m1_review_stats.py](../reports/m1_review_stats.py)，结果在 [runs/m1/review_stats.json](../runs/m1/review_stats.json)。
- **"没过闸门"在统计上站不住**：只跑了一个世界。按用户重抽样，grok-4.7 占标准策略的比例 95% 区间是 [75.7%–85.7%](../runs/m1/review_stats.json)，有 [28.4%](../runs/m1/review_stats.json) 的可能其实低于 80%。
- **闸门本身定错了**：不写记忆、每次都问的策略，任务全部做对，已经拿到标准策略的 [67.4%](../runs/m1/review_stats.json)，80% 的线离它只差一步。换成"在最简单策略之上的剩余空间里拿到多少"，grok-4.7 只拿到 [42.6%](../runs/m1/review_stats.json)（区间 [25.3%–55.9%](../runs/m1/review_stats.json)），离做穿还远。
- **真正的问题：记忆不是必需的**。用户被问到时总会如实回答当前状态，问"最近有什么变化"还会把没讲过的事一次说完。所以记忆只是替 agent 省提问的分（每问 0.15 分）。如果什么都能当场问到，"奖励回传到早先的记忆动作"这个核心问题就没有分量。
- **另一个观察**：grok-4.7 的失分一半来自提问（每次会话 [0.098](../runs/m1/review_stats.json) 分），一半来自选错（[0.089](../runs/m1/review_stats.json)）；选错里最多的是普通的晚餐任务（[6 次](../runs/m1/review_stats.json)），而不是过时记忆或临时情况。晚餐要同时满足的条件最多，这部分难度来自"同时记住很多条"，不是跨会话推理。
- **补充：模拟用户会答非所问（审阅第一遍漏掉了）**。逐条看 grok-4.7 的 [126](../runs/m1/review_stats.json) 个问题，有 [4](../runs/m1/review_stats.json) 个只问"还要不要清淡、能不能吃辣"，却被归到"饮食"话题，用户答的是"没有过敏、饮食上没什么特别限制"。其中 [2](../runs/m1/review_stats.json) 次当场选错。u07 那次最严重：用户第 3 次会话说怀孕了要吃清淡，第 4 次会话 agent 问"孕期的清淡饮食现在还要遵守吗"，这个问题问得对，得到的却是上面那句误导回答。agent 于是在记忆里写下"不再按禁辣处理"，之后 [4](../runs/m1/review_stats.json) 次会话一次都没再问，全部选了火锅。grok-4.7 一共选错 [17](../runs/m1/review_stats.json) 次，其中 6 次可以追到这两处答非所问。所以 0.813 是被模拟用户压低的，环境其实比报告写的更容易。归类器 96.7% 的准确率是在人工编的问题上测的，没覆盖 agent 实际会问的问法。
- **更根本的一层：模拟用户会自相矛盾**。归类只是表面原因。"怀孕后医生让吃清淡"在状态表里落成了"辣度＝不吃辣"，存在"口味"话题下，"饮食限制"那一格仍是"普通"。而"普通"的回答模板是一句全称否定："饮食上没什么特别限制"。每一项的回答都是单独生成的，没有任何一步去核对它和用户自己说过的话是否冲突。所以只要被问到饮食，同一个用户前面说"医生让我吃清淡"，后面就说"没什么限制"。agent 听到这句，得出"限制取消了"，推理本身没有错。三个模型一共碰到 [11](../runs/m1/review_stats.json) 次这种回答（grok-4.7 [4](../runs/m1/review_stats.json) 次、grok-4.3 [1](../runs/m1/review_stats.json) 次、grok-4.20 [6](../runs/m1/review_stats.json) 次），涉及怀孕和嗓子发炎两类健康原因。单纯不爱吃辣的用户说"没什么特别限制"并不矛盾，没有算进去。这也说明，只让 agent 声明问哪一项并不够：agent 完全可能声明问"饮食限制"，拿到的还是这句话。
- **对照研究目标再查一遍：还有四处会让 RL 学错东西，或让我们读错结果**。统计都在 [review_stats.json](../runs/m1/review_stats.json)。
  - **有的变化在台词里完全没有线索**。"开始健身"会把最爱的菜系改成轻食，"怀孕"会改成粤菜，但台词里一个字都没提。agent 只能靠重问才知道，这等于在奖励"每次都问"，而那正是我们要研究的捷径。
  - **选项本身泄露答案**。干扰项在菜系、区域、价位上各有 45% 的概率取正确值，正确值于是成了选项里出现最多的值。一个完全不看用户的规则，只挑"这三项和其他选项撞得最多"的那家，就能选对 [29.1%](../runs/m1/review_stats.json)（晚餐 [35.9%](../runs/m1/review_stats.json)）；随机是 16.7%。RL 会找到这种规律，但它是生成器的瑕疵，不是我们要研究的捷径。
  - **满分参照不可达**。标准策略不用提问，可真实 agent 第一次见到用户时必须问。按"每项只在第一次需要时问一次、变化全部正确更新"估出的理想记忆策略，在和偏好有关的会话上得 [0.918](../runs/m1/review_stats.json)，不是 1。用它做上限，grok-4.7 在剩余空间里的比例是 [54.7%](../runs/m1/review_stats.json)，而不是用标准策略算出的 42.6%。
  - **无关会话在送分**。算账、换算占会话的 12.5%，几个脚本策略会直接答对，另几个是随机选，口径不一致。只算和偏好有关的会话，保守默认从 0.312 降到 [0.214](../runs/m1/review_stats.json)。
- **决定**：
  - M1 闸门改为四道，并换成可达的满分参照，见 README 路线。
  - 第二版先修模拟用户：提问工具让 agent 明确说出问的是哪几项属性，模拟用户只回答这几项，不再用模型猜；同时要求用户的任何回答都不和自己说过的话矛盾，用遍历全部回答的测试来保证。
  - M1 闸门改成三道（见 README 路线）：判分自检；只靠每次都问的策略不超过标准策略的 50%；最强现成模型在剩余空间里的比例，95% 区间上界低于 80%，至少 3 个随机世界。新闸门比旧的更严：第一版过了第三道，没过第二道。
  - 第二版环境优先让一部分信息只在它出现的那次会话里拿得到，使记忆成为必需。CC 列的"变化更隐晦、跨度更长、事件互相影响、多跑几个世界"保留，排在这条之后；"限制记忆条数"先不做，它加的是另一种难度。
