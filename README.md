# good-roommate（好室友）

> Training personal agents that learn, across many sessions, when to ask, what to remember, and when a memory has gone stale — and measuring whether reinforcement learning teaches them the skill or a shortcut.

## 这是什么

一个模拟用户跨越数月生活的训练环境，加上在里面用强化学习（RL）训练小模型个人 agent 的研究。

核心问题：奖励要隔几次对话才到时，RL 教会 agent 的是"记住、适时问、察觉变化"，还是"反复问、选保守默认"这类捷径？哪些环境设计决定它学到哪一种？

## 一个例子

下面的"周"都是环境里的模拟时间，跑完一遍大约只要几秒到几分钟。

| 模拟时间 | 用户说 | agent 应该做的 |
| --- | --- | --- |
| 第 1 周 | "帮我订周五请同事吃饭的餐厅" | 顺口问一句有没有忌口，记下"花生过敏" |
| 第 6 周 | "最近在练健身，教练让我控制碳水，帮我找个能常吃的午饭" | 察觉记忆里的"爱吃面"已经失效，更新饮食偏好 |
| 第 10 周 | "周末请朋友吃饭，帮我订个地方" | 同时满足"花生过敏"和"控制碳水"，选对餐厅 |

第 10 周的分数由代码对照用户当时的真实状态计算，它取决于第 1 周问没问、第 6 周改没改。agent 看不到用户的真实状态。

两种捷径都能拿高分，但都不是我们要的 agent：

- **每次都重问**：提问几乎不扣分时，每次把所有问题重问一遍，不用记也不用推断。
- **保守默认**：永远订一家不会出错的选项，不用了解用户。

## 路线

按顺序推进，每一步过了闸门才进入下一步。

- [x] **M0 查证**：确认研究空白存在
- [x] **M1 造世界，测基线**：四道闸门（第二版：①②③过，④被做穿，见 [M1 第二版报告](reports/m1v2-baseline.md)）。分数只算和偏好有关的会话，算账、换算这类无关会话单独报。满分参照用"理想记忆策略"：每项属性只在第一次需要时问一次，事件带来的变化全部正确更新，从不重问。它代表 agent 实际能拿到的最高分；"标准策略"不提问也知道一切，只用于判分自检。
  - ① 环境自检：判分自检通过；每个长期变化都能从用户台词推出来；模拟用户的回答不和自己说过的话矛盾。
  - ② 记忆是必需的：每次都问、不写记忆的策略，得分不超过理想记忆策略的 50%。
  - ③ 选项不泄露答案：完全不看用户的规则或分类器，选对率不超过 1/6 加 5 个百分点。
  - ④ 环境没被现成模型做穿：最强现成模型在"最简单策略之上、理想记忆策略之下"的空间里拿到的比例，在 3 个随机世界上按用户重抽样的 95% 区间上界低于 80%。
  - ①②③ 过了就进 M2；④ 只报告，不挡路。研究问题是"RL 学到的是真本事还是捷径"，需要的是真本事得分最高、捷径存在、环境没有漏洞，并不需要强模型做不好。④ 只决定论文怎么讲：没被做穿，就是"强模型也做不好的基准"；被做穿了，就是"小模型训到强模型的水平，并拆开看它学到了什么"。
  - 第一版的闸门只看"占标准策略的比例"，已在审阅中作废，原因见 docs/log.md。
- [ ] **M2 第一个训练结果**：闸门是后续任务成功率高于 SFT 起点，且没有学成"每次都问"（起点体检与选型的中期结论见 [M2 起点报告](reports/m2-start.md)）
- [ ] **M3 打开隐式变化**：闸门是使用过时记忆的错误率下降
- [ ] **M4 环境设计对照**：闸门是效应大于随机种子之间的波动
- [ ] **M5 写作与发布**：预印本、公开环境与代码、训练前后的回放演示

## 规则（每一轮都遵守）

1. 判分由代码对照用户的真实状态计算；用到评判模型的地方单独标注。
2. 报告里每个数字都附生成它的日志文件链接。
3. 每一轮结束：更新本页"当前状态"，并在 [docs/log.md](docs/log.md) 顶部追加一条记录。
4. 只用个人账号与个人资源，不涉及任何公司的代码、数据、账号或资源。
5. API 密钥只从环境变量读取，不进入任何文件、日志或提交。
6. 只复用许可证允许公开再分发的资源，并在用到的地方注明许可证。

## 仓库结构

- `research/01-literature.md`：早期调研，主题是编程 agent 的 harness 设计与 RL 训练中的奖励作弊（捷径研究的相关文献）
- `research/02-literature-cross-session.md`：本项目的选题调研与可行性评估
- `docs/log.md`：工作日志
- `roommate/`：模拟环境第二版（只用 Python 标准库和 numpy）。生成模拟用户的"一生"与候选选项、维护用户的真实状态和"告诉过 agent 的值"、提供记忆与按属性提问的工具、按真实状态判分，脚本参照策略、一致性检查、选项泄题检验、台词线索校验，以及接 DeepSeek / xAI 模型跑基线；`python -m roommate.run` 一条命令跑完全部并生成报告（`--offline` 只用缓存）
- `legacy/roommate_v1/`：第一版环境的原样拷贝（提交 d3871eb），只用于报告里 u07 的前后对照；`python -m legacy.run_v1_u07` 用 DeepSeek V4 Pro 在第一版规则下跑 u07
- `roommate/m2.py`、`roommate/m2_report.py`、`roommate/m2_interim.py`：M2 起点体检（经硅基流动调用 Qwen3.5-4B）的运行、统计与报告、只用已跑完部分的中期结论；`python -m roommate.m2 --stages stats,report`
- `tests/`：单元测试（判分自检、模拟用户只答所问与前后一致、选项不泄题、任意会话边界存档恢复、复现、缓存与计费、与外部基准数据的隔离），`python -m unittest discover -s tests -t .`
- `bench/`：外部基准的评测入口（目前是 ATRBench），只在评测时手动运行；基准本身克隆到 `external/`，不进仓库
- `runs/`：每一轮的日志。`runs/m1/` 是第一版，`runs/m1v2/` 是第二版，`runs/m2/` 是 M2 起点体检（请求缓存、账本、中期子集、组内差异子集）；第二版：每个世界的隐藏世界与逐次会话记录、判分自检、一致性检查、泄题检验、台词校验、闸门统计、复现与恢复检查、查价快照、花费账本与逐次调用明细，以及大模型请求缓存（用于不联网复现）
- `reports/`：每一轮的报告，由代码从 `runs/` 的日志生成，每个数字都链接到日志；另有审阅与账本更正用的小脚本
- `external/`（不进仓库）：外部基准的代码、数据和评测输出
